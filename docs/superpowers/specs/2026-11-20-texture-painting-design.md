# CYM 纹理转涂色首版设计

提案 · `feature_texture_mapping` · 基线 `b996232`。产品规格、测试和阶段门槛由 Astra 独立拟稿，接入方案结合当前源码及槽位探针整理。

## 规格

- 从文件菜单或拖拽打开单个 GLB。首版支持静态三角网格、单材质、已有 UV、内嵌 PNG/JPEG 不透明底色图。缺 UV、坏图、外部资源及不支持的材质给出具体错误。硬预算不足时提示原因，允许取消。OBJ、多贴图、图片投影、自动修网和几何光顺进入后续评估。
- 用户可设置色板上限为 1–16 色，与 CYM 的 `MAX_EXTRUDER_SLOT` 一致，并预览转换结果、色板和面数。确认后建立新模型，转换色作为初始面色，画笔及其撤销、重做沿用现有行为。新模型标记为未保存。取消、失败和过期任务保留当前模型、编辑与历史。 [CYM 槽位上限](../../../src-tauri/src/export/paint_color.rs)
- 在现有 3MF 导出面板确认颜色与耗材槽的对应关系。目标机型可用槽数约束导出分配，色板颜色多于可用槽时，由用户确认如何归并。首个实机配置验收使用 Snapmaker Orca / U1。工程回读沿用 0.2 已选的带 `Metadata/cym` 状态的 3MF。移走源 GLB 后仍能恢复逐面颜色及手绘结果，并继续编辑。
- UI/UX 已批准。正式界面跟随 CYM 当前主题，导入预览、编辑与耗材导出均支持深浅两色。主题切换只调整界面外观和视口背景，保留模型与色板的颜色、当前视角、转换设置和已选耗材槽位。 [交互稿](../prototypes/texture-painting-ui-prototype.html) · [CYM 主题](../../../src/theme.css)

## 技术接入

**选 Rust CPU 烘焙。** Three.js 直接贴图适合显示原图。可编辑、可导出的结果统一由 Rust 产生，通过 `MeshDataDto` 接入现有视口。候选库为 `gltf` 和 `image`。先校验 GLB 元数据、资源范围、图片尺寸和预计面数，再加载内嵌资源。按节点变换、米转毫米、Y-up 转 Z-up 的顺序归一几何，负行列式时同步修正面绕序和角 UV。 [glTF 规范](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html) · [gltf 解析](https://docs.rs/gltf/1.4.1/gltf/) · [image 解码限额](https://docs.rs/image/latest/image/struct.Limits.html)

**先复用现有面色模型。** 按几何边共享细分中点，每个面角的 UV 各自插值，避免接缝串色。先验证有面数预算的整网格线性细分和 7 点取色，在采样时处理 UV 包裹、线性颜色和 `baseColorFactor`。复用 `quantize_face_colors` 将颜色压到用户选择的上限。预算须覆盖细分、邻接、索引及 DTO，具体限额由代表模型实测。若同面数下仍丢失小特征，再评估按纹理变化细分。 [现有量化器](../../../src-tauri/src/export/quantize.rs)

**导入先预览，确认才替换。** 文件选择和拖拽复用同一入口。后台按任务 ID 管理候选结果和取消，预览期间保留活动模型。确认后按 STL 构建路径初始化法线、包围盒、标签、KD-tree 和邻接，再提交新模型与 DTO。历史从新网格开始，旧面 ID 不跨导入复用。 [前端导入](../../../src/hooks/useImportModel.ts) · [网格初始化](../../../src-tauri/src/mesh/loader.rs)

**颜色预测留在耗材匹配模块。** 预测接口接收候选槽的稳定 ID、耗材参数和可选工艺上下文，按同一槽 ID 返回估计 sRGB 或未知。首版用可获得的耗材标称色估计，匹配模块用估计色给出槽位建议，未知色由用户手动选择。导出和工程保存读取用户确认的映射。后续在同一接口替换预测实现，已确认的映射继续有效。首版验收覆盖映射一致性和可替换性，实物色差标定留待后续。

**导出使用同一份有序映射。** 现有量化器按面数排槽。用当前 Rust 代码实测，红蓝面数从 3:2 变成 2:3 后，两色槽号互换。用户确认的映射应按色绑定，在导出时生成与当前模型版本绑定的快照，同时供面板、`paint_color` 和耗材配置使用。补画导致颜色新增或超过机型槽数时，重新确认归槽。当前 `main` 的 `.cym` 入口只是前端扩展名。工程回读依赖已在 `feature_020_p0_engineering`（`fbae631`）核对的 3MF 工程链路，槽位映射纳入这次回读验收。 [现有导出命令](../../../src-tauri/src/commands/export.rs) · [3MF 写入](../../../src-tauri/src/export/threemf.rs)

## 阶段与测试用例

| 阶段 | 用例与通过条件 |
| --- | --- |
| 1. 转换正确 | 用带节点变换的 20 mm 非对称色块模型校验尺寸、朝向和 UV 方向。细分改善色界，接缝无串色、几何无裂缝。用纯色分区样例覆盖色板上限 1、16 及 17 色输入收敛到最多 16 色。记录面数、耗时和峰值内存。 |
| 2. 编辑与切片 | 验证取消、坏输入、超预算和过期任务时保留当前编辑及历史。补画后撤销、重做，再使两色面数占比反转，解包核对已确认的槽位。用 16 槽测试配置验证槽 16 的写入。用测试预测器改变建议，确认已接受的映射保持一致。在 Snapmaker Orca 按区域核对 U1 配置的实际挤出路径。 |
| 3. 工程回读 | 接入 0.2 工程能力后保存 3MF，移走源 GLB 再打开，核对网格指纹、面色、手绘结果和槽位映射。重跑 STL 导入、编辑及现有 3MF 导出回归。 |

界面验收覆盖深浅主题下的预览、缺 UV 提示及耗材映射。在设置色板上限和手动分配槽位后切换主题，核对视角、色板和槽位选择。

分支实测与限制见 [实施和验收记录](../plans/2026-11-21-texture-painting.md)。
