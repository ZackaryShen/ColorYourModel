## 三、[blocker] 级发现（必须解决，附 file:line）

### B1 — Phase 0 的判据仪器（HUD）与屏幕不同源，六次"决定性证据"全是仪器读数
- HUD highlighted：`Viewport.tsx:1183` ← `facesBySeg.get(targetLbl).length`，`targetLbl = opts.hoveredSegment ?? clickedLbl`（:1182）
- 屏幕黄色高亮：`Viewport.tsx:1786` 条件 `hoveredSegment !== null && !giantSegmentIds.has(hoveredSegment)`，渲染源是 **store 的 `hoveredSegment`**（:1788）
- 三重分叉：① HUD 用 `targetLbl`（含 click 回退 + `lastValidHoveredSegmentRef` 复活值），屏幕用 store 值；② HUD **不过 `giantSegmentIds`**，屏幕过；③ hover=null 时屏幕渲染 0 面，HUD 报 clickedLbl 全量。
- 推论：journal 六条 `seg=0(click)` 读数意味着 store `hoveredSegment` 恒为 null → `:1786` 高亮组件根本没渲染 → 屏幕高亮面数=**0 不是 1498252**；且主诉是"Fill **>** 高亮"（溢出），HUD 数据 `12 << 1498252` 方向相反。七版修复建立在自相矛盾的读数上。
- whole-segment 路径下 HUD 是同义反复：后端返回该 label 全部面，HUD 再拿 `facesBySeg.get(同 label)` 比 → 恒 ✓，测不出"填的与看到的是否一致"；陈旧 hover 填错区时给**假 ✓**。
- **违反 C3「取证优先于修改」**。修正：Phase 0 前插 iter31a 校准仪器。

### B2 — 闸门统一后 A4 按字面判据仍必挂（隐性 blocker）
点 seg=0（share≈1.0）：hover 侧 giant→不高亮→0 面；fill 侧降级 `fill_paint(radius)`（usePaintTool.ts:146-150）→12 面；12≠0→仍 MISMATCH。降级是 FR-PNT-02 有意设计，闸门统一只让"决策一致"≠"面集一致"。叠加 D2 未决 → "整段填充"语义未定义。

### B3 — 顺序与 docs/04 既有结论冲突且两出口都错
`docs/04:128` 顺序 `P0-2→P0-1→P0-3`，`docs/04:139` 明写「P0-2 是 P0-1 结构性成因」。候选路线图 Phase0=验 P0-1、Phase1=P0-2 **顺序颠倒且未说明为何推翻**。两 EXIT 都失效：收敛只证"这次没降级"；不收敛极可能是 B1 假阳性。

### B4 — v7 sticky 引入"永久 hover 钉死"活体缺陷
- `Viewport.tsx:1477` `let nextHover = prevHover`（miss 时不清）
- `Viewport.tsx:1484` `if (!(prevIsManual && lbl < MANUAL_SEGMENT_OFFSET)) nextHover = lbl` — manual 入驻后任何 auto 段永远无法覆写
- 唯一清除点：`:1585`（pointerleave）与 `:1328`（切套索）；fill 优先取 hover（usePaintTool.ts:107）
- → 用户 hover 过一次手动区后，只要指针不离开画布，之后在模型任意位置点 Fill 都填那个手动区。Phase 0 回归脚本**必须含反例**：hover 手动区 A → 移到模型另一端 auto 区 B → 点 Fill，预期填 B，实测填 A。

### B5 — P0-3 把治标当治本，根治会撞 PRD 铁律
- fill 取 hover：`usePaintTool.ts:107` `const label = (hovered != null) ? hovered : (md?.segmentLabels?.[faceId] ?? undefined)`
- 陈旧 hover 是刻意实现：`Viewport.tsx:1236-1237` `hoveredSegment: snap ?? lastValidHoveredSegmentRef.current` — store 空时主动复活历史值（iter29 v5）
- 在此加 TTL 安全阀三重无效：① pointermove 不记时间戳，TTL 无基准；② "面数上限"是第三套闸门，与 P0-2 要统一的两套再次分叉；③ 修不了 B4（钉死的是"新鲜"值）。
- **根治**：fill 改以 click 命中面的 segment 为准，删 `lastValidHoveredSegmentRef` 整条通路。但与 `FR-PNT-03` 冲突 → 属 PRD 级变更，须先裁决 D1。

### B6 — 3MF 不兼容风险源码级已可判定，绝不能等到 Phase 4
`src-tauri/src/export/threemf.rs`：
- `:84` `m:basematerials`、`:95` `m:base` 属核心规范默认命名空间，不属 Materials 扩展（`xmlns:m`）
- `:112` `("m:basematerials","1")` 两规范都不存在此属性；核心规范用 `pid`/`pindex`
- `:149-150` 三角形 `pid="1" p1="..."` 引用的 resource id=1 因上条未注册成功 → **悬空引用**
- `<build><item objectid="2"/>`（:174-185）存在 → 几何体会显示，颜色极可能整体丢失或报错。
- **export 模块零单测**（docs/04 称"fixture 单测"不准确，实际一个都没有）。修正：A9 前移并行，先补单测打 XML 对规范逐条比。

### B7 — A6 从未在目标规模验证，P0-3 前提不成立
- 快照：`Viewport.tsx:1351-1354` `pushUndo(...)` 每次 pointerdown **同步**执行；150 万面→单次快照 ≈12MB，栈上限 `appStore.ts:343` `slice(-19)`→20 层→常驻约 240MB
- 回滚 IPC：`useTauriCommand.ts:189` → 后端 `restore_face_colors`（segment.rs:272-276），Tauri 把两数组序列化为 JSON 数字数组 → 单次撤销传 600 万+150 万个十进制数；A6 要求 10 次撤销+重做=20 次往返
- P0-3 立论（"撤销栈可能不足以完全回滚"）依赖 A6，而 A6 本身可能是独立 blocker。A6 必须与 Phase 0 并行验证，用例须 150 万面 + Fill 大分区。

## 四、[major] 级发现

### M1 — 闸门不对称真实存在，但候选方案描述与签名都错
| 维度 | hover `giantSegmentIds`（Viewport.tsx:1028-1040） | fill `fillWholeSegment`（usePaintTool.ts:125-130） |
|---|---|---|
| 人口 | `autoSegs = segs.filter(id<100000)`（:1033） | `realSegs = segs.filter(faceCount>0)`（:122）**含手动区** |
| 数量分支 | `autoSegs.length<=1`→静音全部 auto（:1034-1036） | `realSegs.length>1` 才允许整段（:129） |
| 占比阈值 | `faceCount > total*0.8`（:1038-1039） | `share <= 0.8`（:129） |
| 手动区 | `id>=100000` **无条件豁免**（:1033/:1039） | 豁免但受 0.95 上限（:128） |
| 额外闸门 | v7 sticky `!(prevIsManual && lbl<100000)`（:1484） | **无对应物** |
| 常量可见性 | 仅 `WHOLE_SEGMENT_MAX_SHARE`、`MANUAL_SEGMENT_OFFSET`（:7） | `MANUAL_REGION_MAX_SHARE` 仅 usePaintTool.ts:16/128 |

- M1-1：手动区豁免两侧语义不同（hover 无条件 / fill ≤0.95）→ 统一到哪侧是产品决策（D5）。
- M1-2：拟议签名 `shouldWholeSegmentFill(segId, share)` 表达不足——`autoSegs.length<=1` 与 `realSegs.length>1` 需完整 segments 列表，至少需 `(segId, segments, total)`；否则会静默丢掉数量分支制造新不对称。
- M1-3（docs/04-P0-2 未记载的第三处不对称）：`autoSegs.length<=1` vs `realSegs.length>1`。反例：1 auto + 2 manual → hover 静音该 auto（length=1），fill 却允许整段（length=3）→ 填 N 面/高亮 0 面。
- M1-4：REFUTE 目标应改为"同一 `(segId, segments, total)` 输入下返回同一布尔值"，非"字节一致"。

### M2 — P1-6 应写成条件门，非无条件放 Phase 6
`appStore.ts:418` `version:1` 无 `migrate` 属实；`:435` `merge: mergePrefs`、`:124-126` 范围校验、`:198` `clamp` 已在 → FR-PRF-04 满足。真风险：Phase1 若把 0.8/0.95 做成偏好项或 Phase3 安全阀阈值进 `partialize`，存量用户升级后旧值覆盖新默认 → A7 表面过但行为回退。⚠️ 反论据：`:110-115` B1 注释明写「不要用 migrate」——仅针对 legacy `cym-theme` 键，补 migrate 前须在 journal 限定该注释范围（同类 P1-3 陷阱）。**条件门**：若 v0.1 未改 `partialize` 8 项默认值→留 Phase6；一旦触碰→升级为发版前必做。
