## 3. 可优化点（含风险与差异）

| # | 优化点 | 证据 / 风险 | 建议 |
|---|--------|-------------|------|
| 1 | **测试套件缺失（高优先级）** | `tests/__init__.py` 仅含 `"""测试模块"""`，无 `cargo test`、无 `vitest`。与项目自身「对抗式开发循环」的 TEST 步骤直接冲突——当前零自动化验证 | Rust 单测覆盖 `dihedral` 合并与 `loader` 去重；前端 `vitest` 覆盖 store/hooks |
| 2 | **版本号未更新** | `package.json` `version=0.1.0`，但 README/CHANGELOG 描述 v0.2 功能已完成（差异） | bump 至 `0.2.0` |
| 3 | **调试日志写入源码目录** | `dihedral.rs:10` `seg_log` 写 `CARGO_MANIFEST_DIR\segment_debug.log`；打包后该路径为编译期常量（构建目录），运行时不保证可写，且无条件 `append` | 路由到应用日志目录，并以 `RUST_LOG` 门控 |
| 4 | **3MF 仅实色（basematerials）** | `threemf.rs` 用 `m:basematerials(displaycolor)`，不支持顶点色插值 / 纹理；对渐变或多材质场景存在上限 | 增加 `colorgroups`/`texture2d` 选项；并做 OrcaSlicer 往返兼容验证 |
| 5 | **分支纪律** | 当前 `git` 位于 `main`（无 `feature/bugfix` 分支）。项目 R6 规则要求不在 master 开发 | 新功能开 `feature_*` / `bugfix_*` 分支 |
| 6 | **文档与代码表述微差** | README 称「三阶段」分割，代码实为四阶段（Phase 2 为 RAG 构建，非合并）（差异） | 统一文档措辞 |
| 7 | **无 CI** | 无 GitHub Actions 运行 `tsc` + `cargo check` + build | 补充最小 CI 流水线 |
