## 2. 裁决引发的三项结构性结论

### 2.1 三个 P0 由同一次「删除式重构」解决

原 4 个 P0 阻塞中，前三个在裁决后不再是独立缺陷，而是**同一个根因的三种表现**：一套「hover 优先 + 占比阈值降级」的机制引入了两条各自演化的决策路径。

| 原 P0 | 裁决后处置 | 依据 |
|---|---|---|
| P0-1 Fill 范围与高亮不一致 | fill 与 hover 都取 click 命中的 label，都整段填充 → 面集**结构性相同** | D1 + D2 |
| P0-2 hover/fill 闸门不对称 | 两侧阈值与数量分支**全部删除**，不对称的载体消失 | D2 |
| P0-3 陈旧 hover 无安全阀 | hover 不再决定 fill 目标，陈旧值无害 | D1 |

这满足 backlog **M5** 提出的「必须换角度」要求：过去 7 轮都在**修补** hover 传递链路，本轮是**移除** hover 的决策权。删除比统一更彻底 —— 没有第二条路径，就不会再次分叉。

> ⚠️ 但 **B1（HUD 仪器与屏幕高亮不同源）仍须先修**。理由：即便一致性变成结构性保证，回归验证仍需可信读数，否则无法证明重构没引入新缺陷。Phase 0a 保留。

### 2.2 D2 的隐藏代价：高亮渲染性能（新增风险，原 backlog 未记载）

`SegmentHighlight`（`Viewport.tsx:591-610`）在 `useMemo` 中**同步重建** geometry：

```
for (const f of selectedFaces) { pos.push(9 个 float) }   // :600-607
new Float32BufferAttribute(new Float32Array(pos), 3)      // :609
g.computeVertexNormals()                                  // :610
```

150 万面分区 → 450 万顶点 → **5400 万次 `Array.push`** + 一次 216MB 的 `Float32Array` 分配 + 全量法线计算，全部在主线程同步执行。

**这才是 `giantSegmentIds` 静音机制存在的真实原因**（此前被记录为 UX 考量）。D2 取消静音后，若不改造高亮构建方式，hover 大分区将直接卡死。

处置：Phase 0d 先实测量化，Phase 1 按实测结果落地方案。候选方案：

| 方案 | 做法 | 预估收益 | 风险 |
|---|---|---|---|
| **β（首选）** | 高亮改用 **indexed BufferGeometry**：复用主 mesh 的 `position` attribute，只构建 index 数组 | push 次数 5400 万 → 450 万（12×），省掉 216MB 分配与 `computeVertexNormals` | 需确认主 mesh geometry 是否为非索引展开式；若是，须先建顶点去重映射 |
| α | 复用主 mesh，用 `vertexColor` attribute 局部覆写实现高亮 | 最优，仅写 Uint8 attribute | 与现有材质/主题色系统耦合，改动面大 |
| γ | 大分区高亮异步构建 + 过渡态 | 不卡主线程 | 高亮延迟出现，A4 判据取证变复杂 |

### 2.3 D4 取证结论：「拆分」已实现，缺口仅「合并」

**H1 证实** —— `finalize_manual_region`（`src-tauri/src/segment/manual.rs:578-582`）无条件覆写 `mesh.segment_labels[f] = label`，源码注释明写 *"faces may belong to an earlier region"*，并以 `ManualRegionSnapshot` 记录原 label 供撤销。`paint_segment_face`（`src-tauri/src/commands/segment.rs:122-123`）同理。

→ 用户用套索或分区笔在任意已有分区内圈出一块，该块 label 被覆写为新手动 label，原分区自动少掉这部分。**这在功能上就是拆分。**

现存差距（记为 v0.2 候选，不阻塞 v0.1）：拆分产物恒为手动区（label ≥ 100000）；无「选中分区 → 按 SDF 自动细分」能力；UI 未以「拆分」命名，用户可能不知道该功能存在。

**H2 证实** —— 后端命令清单（`src-tauri/src/commands/`）中**无任何 merge / split / relabel 命令**。合并需从零实现。

有利条件：`SegmentsPanel.tsx` 已存在，store 已有 `selectedSegment` 单选态（`SegmentsPanel.tsx:13/33`），Viewport 已消费其高亮渲染（`Viewport.tsx:1797-1801`）。合并只需扩多选 + 一个后端命令。
