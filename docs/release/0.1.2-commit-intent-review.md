2. **霰弹式修改（Shotgun Surgery）——明显**
   `src/store/appStore.ts`（858 行）把每个功能的视图态都塞进单一 zustand store：`mergePicked`(54)、`viewSelectedRegions`(201)、`hiddenSegments`(196)、`seedPoints`(228)、`suggestedSeeds`、`seedEraseMode`、`experimentalFeatures`、`importError`、history flags 等。每个新 issue 都触碰 appStore + component + hook + i18n + types 五处（spec 实验特性一节自述「store 五件套」）。这是 store 收敛过多职责的典型表现。

3. **基本类型偏执 + 缺领域类型（Primitive Obsession）——严重，且是两次 bug 的直接根因**
   坐标被表示为裸 `number`/`[number,number,number]`，空间语义（model-local vs world）只写在 doc-comment 里（`src/types/mesh.ts` 的 `SeedPoint`「model-local」注释；分析文档 §3.1 逐条靠读注释推断）。正是这种「空间靠注释、不靠类型」导致 R6–R8 反复把局部种子喂给世界相机 API。`meshData.vertices`/`faces` 是平铺 `number[]`（`993f0b7` 的播种漂移即 `fi=faceIndex*3` 索引错误）。一个 `LocalPoint`/`WorldPoint` 新类型（或至少 branded type）本可在编译期拦截整条 R6→R9 线。

4. **重复代码（Duplicated Code）——明显**

   `src/hooks/useSegmentMerge.ts`（51 行）只是把 store 的 `mergePicked` + `useTauriCommand().mergeSegments` 串起来，价值在收敛而非抽象，可视为薄中间人。

10. **神秘命名 / 数据泥团 / 拒绝遗赠**：未发现实质证据（无类继承体系；命名整体清晰）。
