## 1. 版本一致性 — ❌ 未通过

三处版本号当前**一致**（都是 `0.1.1`），但发版需统一改为 `0.1.2`：

| 文件 | 行号 | 当前值 | 需改为 |
|------|------|--------|--------|
| `package.json` | 4 | `"version": "0.1.1"` | `0.1.2` |
| `src-tauri/tauri.conf.json` | 4 | `"version": "0.1.1"` | `0.1.2` |
| `src-tauri/Cargo.toml` | 3 | `version = "0.1.1"` | `0.1.2` |

关联事实（都基于同一版本源，无需额外手工改动，但要确认）：
- `vite.config.ts:12-14,20-21` 从 `src-tauri/tauri.conf.json` 读取 `version` 注入 `__APP_VERSION__`；关于框显示 `v${__APP_VERSION__}`（`src/components/MenuBar.tsx:257`）。改 `tauri.conf.json` 即自动生效。
- `vite.config.ts:7-11` 注释明确「版本单一事实源是 tauri.conf.json」，并警告「只 bump package.json 会让 updater 永远重复提示（REFUTE M8）」。因此**三个文件必须一起改**。
- `src-tauri/Cargo.lock:647-648` 存有 crate 自身 `version = "0.1.1"`，由 Cargo.toml 生成，随 `cargo build/check` 自动更新，无需手改。

**动作**：三处同时 0.1.1 → 0.1.2。

## 2. CHANGELOG.md — ❌ 未通过

- `## [Unreleased]` 位于 `CHANGELOG.md:41`，发版时需改为 `## [0.1.2] — <日期>` 并加日期。
- **排序违反 Keep a Changelog**：`## [0.1.1] — 2026-10-04`（行 7）排在 `## [Unreleased]`（行 41）**之前**。正确顺序应是「最新版（0.1.2）在最上 → 0.1.1 → 0.1.0」。
- **`[Unreleased]` 段落混入大量 0.1.1 之前日期的条目**，不应属于 0.1.2。真正属于 0.1.2 的是 `2026-10-24` 之后的条目（行 43–84：种子橡皮擦、#28 重置确认、#29 替换颜色、多选统一、隐藏分区涂改修复、#23 已用颜色、#24 分区显隐、#22 历史面板、#21 拖拽导入、#20 整笔撤销）。但行 85–218 还夹着 2026-09-29、2026-09-08、2026-08-29/28/27、2026-08-07 的历史条目（`### Known Issues — 开源前…`、`### Changed — 根目录不再生成 HTML…`、`### Added — 开源准备…`、`### Removed — 导入时自动分割…` 等），这些要么归入 0.1.1/0.1.0，要么归档，不该留在 0.1.2 段。
- **格式非标准 Keep a Changelog**：用了自定义子标题 `### Added — 标题（#issue，日期）`、`### Verified — …`、`### Changed — …`、`### Known Issues — …`，而非标准 `### Added / Changed / Deprecated / Removed / Fixed / Security`。
- 底部 `## 对抗式开发日志`（行 241）为项目特有的迭代记录，非版本段落，可保留为附录但不属于 Keep a Changelog 主体。
- `## [0.1.0] — 2024-12 (初始版本)`（行 222）日期可疑：README 明说「v0.1.0 2026-09 发布」（`README.md:220-222`）。

**动作**：改标题、把 0.1.2 段置顶、按日期归位历史条目、收敛为标准子标题（至少对 0.1.2 段）。
