# 按颜色分件导出 — 技术验证结论（0.2.0-P2 spike）

> 状态：代码已落地（`export::split`，文件菜单「按颜色分件导出…」），本文记录 spike 要回答的三个问题与结论。

## 实现概要

涂装颜色先走 3MF 同款中位切量化（≤16 槽，`MAX_EXTRUDER_SLOT`），每个槽内再做面邻接连通片拆分（同槽 = 同件），每片抽取为独立 MeshModel（顶点重映射、继承原始逐面涂装）并导出 OBJ + `manifest.txt`（件名/槽位/RGB/面数）。件名 `part-SS-KK.obj`：SS=颜色槽（按面数降序，与 3MF 槽位一致），KK=槽内壳序号（BFS 自最小面索引起，跨次导出稳定）。

## 问题一：开放面壳切片器接受吗？

CYM 拆出的件是**开放曲面壳**（该颜色的表面，无封面），全仓无封洞代码。结论：这是本特性最大的未验证风险——Cura/PrusaSlicer 的切片算法对非水密网格通常报错或静默丢弃（"模型不封闭"）。**真机切片验证需在解锁环境人工完成**（导入 part-*.obj 到 Cura 观察切片结果）。在验证通过前，此功能对 Cura/PrusaSlicer 的可用性标注为「未证实」；OBJ 本身可被 Blender/MeshLab 正常读取（几何有效）。

## 问题二：16 槽上限

与 3MF 导出同源的中位切量化把颜色压缩到 ≤16 槽，分件数量 = Σ(每槽连通片数)。多色渐变模型（渐变画笔产出数百种中间色）会被量化到很少的槽——分件结果与视觉渐变不一致，属预期行为（渐变本身就是连续色，分件打印场景应使用有限色板）。

## 问题三：顶点重映射正确性

`extract_submesh` 按使用顺序重映射顶点（HashMap 保序），单测断言了每件 OBJ 的 `f` 索引 ≤ `v` 计数；两句 OBJ 只有 v/f 行（无 vn/vt），`compute_normals` 只影响渲染。

## 结论

- OBJ 分件：已实现，几何有效，**切片器可用性待真机验证**（开放壳）。
- 3MF 多 object 分件：未投入——在开放壳问题解决前无意义。
- 后续路径：若真机验证失败，选项为 (a) 体素封洞（重）、(b) 平面盖板封闭（轻，颜色边界沿边延伸 + 平面盖）、(c) 放弃分件、引导用户使用带涂色槽的 3MF 工作流。
